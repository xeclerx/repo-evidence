# Как внести вклад

Спасибо за интерес к RepoEvidence. Особенно полезны новые детерминированные правила, небольшие fixture-репозитории, исправления безопасности и улучшения объяснимости отчёта.

## Перед началом

1. Проверьте существующие issues.
2. Для заметного изменения сначала создайте issue и опишите пользовательскую проблему.
3. Не публикуйте уязвимости в открытом issue — следуйте [SECURITY.md](SECURITY.md).

## Локальная разработка

```bash
git clone https://github.com/xeclerx/repo-evidence.git
cd repo-evidence
uv sync --extra dev
uv run pre-commit install
```

Создайте отдельную ветку:

```bash
git switch -c feature/short-description
```

Перед pull request выполните:

```bash
uv run ruff check .
uv run ruff format --check .
uv run mypy src
uv run pytest --cov
```

## Требования к правилам анализа

Новое правило должно иметь:

- стабильный ID и версию;
- категорию и фиксированный вес;
- детерминированные условия без исполнения анализируемого кода;
- русское объяснение результата и практическую рекомендацию;
- доказательства с путём к файлу и строкой, когда это возможно;
- тесты для `passed`, `partial` или `failed`, а также `not_applicable`, если он допустим.

## Pull request

- делайте один логический change на pull request;
- добавляйте тесты и обновляйте документацию вместе с кодом;
- объясняйте не только что изменилось, но и зачем;
- не включайте форматирование или рефакторинг несвязанных файлов;
- убедитесь, что в diff нет `.env`, токенов и локальных данных.

Отправляя вклад, вы соглашаетесь на его распространение по лицензии MIT проекта.
