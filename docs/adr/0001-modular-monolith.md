# ADR-0001: Модульный монолит и отдельный worker

- Статус: принято
- Дата: 2026-08-07

## Контекст

Продукту нужны HTTP API, история отчётов и потенциально тяжёлый статический анализ. Микросервисы увеличили бы операционную сложность до появления независимых нагрузочных профилей и команд.

## Решение

Использовать модульный монолит с направлением зависимостей `presentation/infrastructure → application → domain`. Анализ выполняется отдельным Celery worker, но использует тот же application и domain-код. PostgreSQL является источником истины, Redis — только брокером задач.

## Последствия

Доменный scoring можно тестировать без web и БД. API и worker развёртываются независимо, при этом схема данных и релиз остаются едиными. Если анализаторы потребуют независимого масштабирования, их можно выделить за существующим application-интерфейсом.
